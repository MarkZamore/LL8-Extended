# Files this pack owns outright.
#
# An instance is merged from the pack three ways, and a file that matches
# neither the pack's old copy nor its new one is taken for the player's work
# and left alone. That is right for a setting somebody tuned by hand and wrong
# for a file a mod rewrites on its own - such a file looks edited from the
# first launch, so nothing shipped here could ever reach it again.
#
# Everything listed below is written over instead. What was there is copied
# into the instance's conflicts folder first, as name.user-file, so a change
# somebody did mean can be put back. Keep this list to files the pack really
# decides: anything a player is meant to tune belongs outside it.

# Agritech generates these three from whatever is installed, and it generated
# them while Regions Unexplored and Oh The Biomes We've Gone were still here.
# Every line naming a block that no longer exists became an error while the
# recipe screen was built - about 8,900 of them in one launch - and the mod
# rewriting its own tables is exactly what made the corrected ones unreachable.
config/agritech/*.json
config/agritechevolved/*.json
config/agritechtrees/*.json

# Yes Steve Model rewrites its config on start, and this is the file it reads:
# a SERVER config lives in config/, and a copy under saves/<world>/serverconfig
# only overrides it for that one world - the readme NeoForge writes into that
# folder says exactly that. The pack sets the model a player starts on, so the
# claim has to stay: a file the mod rewrites looks edited from the first launch,
# and without this line the launcher would take it for the player's own work and
# never put the pack's copy back.
config/yes_steve_model-server.toml

# Global Packs writes its own config on start, and this one is what makes the
# build's resource packs impossible to switch off or reorder: its enable_builtin
# list names every pack the build locks, and the two it does not name are the
# two a player may change. Without this claim the file an instance already has
# would keep the mod's own empty list and the lock would never arrive.
config/global_packs.toml

# The Netherite Octoarachnopod is gone and its config no longer ships. The claim
# stays because that is what takes the old file back out: a file the pack once
# installed and then stopped shipping is only removed from an instance while
# the pack still owns it.
config/arachnomod-common.toml

# How fast an item slides between slots; the mod rewrites this file itself.
config/smoothswapping.json

# The backup schedule. SimpleBackups rewrites its config on start, so without
# this claim the incremental schedule shipped here would never reach a player
# whose instance already exists.
config/simplebackups-common.toml

# KubeJS writes this one itself the first time it starts, so the copy shipped
# here never reached an instance that already existed - and the HTTP and
# WebSocket server it opens on localhost:61423, which this pack has no use for,
# went on listening.
kubejs/config/web_server.json

# Immersive Optimization rewrites its config too, and it stamps a version into
# it, so an instance that has run once has a file that looks edited by hand.
config/immersive_optimization.json

# Sky Aesthetics generates both of these itself - which is why there are two
# spellings of one name - so the cleaned copies here would otherwise stop at
# the sync. Nothing in either file is meant for a player to tune: they name
# mods and dimensions this pack has, and one of those names was a mod it no
# longer has.
config/sky-aesthetics.json
config/sky_aesthetics.json

# Quark is the one mod here that can take its own optional pack off the
# resource pack screen, and "Generate Programmer Art" is that switch. It is off:
# hiding is the one thing locking cannot do, because locking a pack switches it
# on. Quark rewrites this file on start, so the switch only reaches an instance
# that already exists by being claimed.
config/quark-common.toml

# Ice and Fire draws its own name and version into the corner of the main
# menu, and customMainMenu is the switch for it. The mod writes this file on
# first start, so an instance that has already run has one of its own and
# nothing shipped here would reach it. The two other settings in the file
# keep the values they had.
config/iceandfire/iaf-client.json
# the long night, the torches swapped for redstone ones and the torches broken are off in it; the mod writes this file itself on the first launch, so without this line the pack could never change them again
config/serversidehorror.json
# its login guard refuses an offline UUID and kicks a late auth challenge - both aimed at somebody else here, where the identity is the launcher's and the lateness is EMI rebuilding its index on the joining client
config/identity2.json
# the disconnect timeout is five minutes rather than one, because a guest is frozen up to a minute inside that same EMI reload while the host hands them the registry of 880 mods
config/connectivity.json

# The teleport warmups are zero here: no three second wait before /home or
# an accepted /tpa, and nothing to cancel by stepping aside. FTB Essentials
# rewrites this file on start, so an instance that has ever run has one that
# looks hand-edited and the pack's copy never reached it - the warmups
# shipped as zero and stayed at three for everybody who already played here.
# The whole file comes with the claim, which is the trade: every other
# setting in it is the pack's to decide as well.
config/ftbessentials.snbt

# Lootr rewrites its client config at every start, the same way FTB
# Essentials does, so a change shipped here would look like the player's
# own work from the first launch and never reach them again.
config/lootr-client.toml

# EMF rewrites its settings file at every start, so the chest models
# switched off in it have to be written over the same way.
config/entity_model_features.json

# And the file the launcher seeds that one from when it is missing. It is
# not read while the live config is there, but it holds the mod's own
# numbers, and a stale copy of them is the first place to look when the
# live config keeps coming back with the defaults in it.
defaultconfigs/ftbessentials-server.snbt

# AsyncParticles keeps its mixin switches here and stamps the file with the
# time it last wrote them, so an instance that has started once differs from
# the pack copy by that single line and looks hand-edited from then on -
# nothing changed here would ever reach a player again. The switch the claim
# is for is safeClassInstanceMultiMap: the mod runs animateTick off the main
# thread, Burnt's grass looks entities up inside it, and ClassInstanceMultiMap
# cannot be read while the main thread writes it. The game said so in chat on
# every occurrence; now the map is locked instead.
config/asyncparticles/asyncparticles-mixin.properties
